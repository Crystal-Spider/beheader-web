# Milestone 3 — processing foundation

Completed on 2026-10-16. Format composition starts in Milestone 4; the interface still disables file selection and generation.

## Deliverables

- Framework-independent contracts for input inspection, composition planning, generation, safe diagnostic codes, measured progress, cancellation, interpretation metadata, and output references.
- One lazily created dedicated worker per operation, with a runtime-only Angular owner. Files, workers, readers, streams, and storage handles are never stored in NgRx or preferences.
- Signature and metadata-hint detection for the five families: image, media, HTML, PDF, and archive. Conflicting candidates require an explicit role assignment through `FileInput.role` and reinspection. The generator interface for choosing roles belongs to Milestone 8.
- Immediate validation of 1 GiB per input and 2 GiB total before any byte reads. Auxiliary files are included in those limits. One image/media/HTML/PDF slot, ordered multiple archives, and separate HTML-assets/appendable/extra-header roles.
- Seekable Blob/File reads and a backpressured output writer with bounded 1 MiB operations, offset validation, in-place patching, caller-selected output limits, and fail-closed behavior after a write failure.
- Job-scoped OPFS storage under `beheader-web-polyglot-v1`, with opaque UUID paths, file-backed results, unfinished-stream aborts, and explicit cleanup failures. Cancellation terminates the worker before deleting its generation workspace.

## Limitations and next boundary

Detection is provisional evidence, not validation of a file's full structure or a generated interpretation. Animation, MP4 boxes/codecs/encryption, PDF structures, archive integrity/expanded limits, and actual consumer compatibility are validated in their respective format milestones. No family combination is currently advertised: plans return no supported interpretations and explicitly report `IMPLEMENTATION_UNAVAILABLE`; generation cannot produce an artifact yet.

The 1 GiB copy test uses a virtual source and a counting sink, not a real 1 GiB disk/media workload. Actual browser I/O is exercised with a small disk-backed fixture. Resource estimates, available-quota preflight, abandoned-job recovery, cross-tab coordination, offline reopening, and complete large-job resilience remain Milestone 9 work. A browser/process crash can leave an abandoned UUID workspace until that recovery path exists.

Firefox, WebKit, actual Safari/iOS, Android, and other consumer applications remain unverified. No image/media/PDF/archive output acceptance is claimed. No deploy workflow was added or run. Stop before Milestone 4 for review.
