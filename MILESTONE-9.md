# Milestone 9: offline operation and large-job resilience

Implemented on 2026-10-16. This milestone adds production offline caching, idle-only updates, storage preflight/accounting and cross-tab-safe abandoned-workspace recovery. AGENTS.md remains local; stop before Milestone 10.

## Offline operation and updates

Pinned Angular service worker 22.2.3 generates a versioned cache beneath /beheader-web/. Its prefetch group includes the shell, all lazy JavaScript chunks, processing workers, both bundled translation catalogs, local icons/flags, examples, license assets, and the focused AAC encoder's embedded WASM/helper code. There are no remote processing assets or data-cache groups for user content. Selected Files, generated outputs and diagnostic details never enter the application cache.

The interface reports offline readiness after service-worker registration and initialization. A warmed app can close its page, reopen offline in the same browser profile/context, switch language, select local examples, convert audio and download a result without network responses. Offline reopening requires the initial successful cache, HTTPS or localhost, and retained browser site data. Clearing/evicting site data removes offline availability. Development ng serve intentionally does not register the production worker; use pnpm build followed by pnpm preview to test offline operation.

Ready updates are surfaced as an explicit reload action, disabled while any inspect/plan/generate/cleanup operation is active. The handler checks the same busy state, so an active operation cannot be interrupted by the action. Reloading keeps hashed lazy chunks consistent and explicitly clears selected files/results. No automatic mid-job activation or forced reload is used. The update-gate browser check injects Angular's version-ready event; it verifies gating and an actual reload, rather than claiming a real deployed-version upgrade was tested. Real deployment acceptance remains Milestone 10.

Every generated docs/ asset is preserved byte-for-byte by Git attributes. This is necessary for service-worker content hashes as well as the AAC encoder's inline WASM string. Committed manifest hashes are checked against staged asset bytes before commit.

## Storage and large jobs

All jobs use the existing bounded file-backed path, including inputs above 512 MiB and selections whose aggregate/intermediate estimates cross that threshold. Plans expose an informational temporary-storage estimate and a large-job flag. Before generation, navigator.storage.estimate is checked against known minimum simultaneous payload bytes. Missing/failed estimates permit a bounded attempt; an estimate cannot guarantee free physical space. Estimates do not reject a potentially compressible job based on an optimistic or pessimistic compression ratio.

Every actual positioned OPFS write reserves its file's high-water size in a job-wide budget before growing storage. Patches do not count twice, and successfully discarded intermediates release their reservations. The live temporary-byte cap is 4 GiB, alongside the existing 2 GiB per-output/intermediate limit, 1 GiB per input, 2 GiB total input and strict archive-expansion limits. Read/write chunks remain at most 1 MiB. Existing metadata, image, parser and packet bounds remain in force. Quota failures, output/resource bounds and cancellation retain stable diagnostics and dispose partial workspaces where recovery is possible.

Each live app tab holds a shared Web Lock for its session, including retained download outputs. Startup cleanup requests an exclusive lock only if immediately available, so another live tab's work is protected. When no live app session remains, the next visit removes UUID job directories only inside beheader-web-polyglot-v1. Other applications' origin data and unrecognized entries are preserved. Without Web Locks, automatic cleanup is conservatively skipped rather than risking another tab's work. Maintenance failures are reported as recoverable storage diagnostics. Forced tab/browser termination releases browser-held leases; abandoned files are handled on reopening. No selected files are restored.

## Evidence and reproduction

The milestone exit suite includes frozen installation, lint, strict application/tooling/worker types, 113 unit tests, 82 Chromium flows, the existing audio matrix (32 functional Chromium/Firefox flows and three capability probes, with 16 reviewed Windows WebKit skips), and a production build. Independent advanced/26-combination/audio/image/media checks are retained.

New browser checks verify offline close/reopen, both languages and lazy AAC conversion from cached assets; idle-only update application; live-tab storage protection; preservation of other origin/app data; cleanup after closing a tab during actual audio conversion; and cancellation of a large streaming composition.

The large-job check generates an actual file above 512 MiB using a synthetic seekable appendable, HTML and a classic PDF. It exercises the real core writer and OPFS, then downloads the file through the browser's file-backed object-URL path. The downloaded size matches the artifact, all 512 MiB + 1 payload bytes are checked by streaming SHA-256 comparison, Poppler independently recognizes one PDF page, and no requested source read exceeds 1 MiB. The downloaded artifact is 536,871,924 bytes; the verified 536,870,913-byte payload has SHA-256 1422bc3f6e9004d5ccb31c4dc2d77867c1084525354031d9ce40bc53d99e3c6c. The ignored test-results/large-validation.json records this evidence. This fixture establishes this path on the tested Windows/Chromium environment; it does not establish successful 1 GiB inputs or maximum-size conversion on every device. Native direct-to-file saving is not required for this verified path.

Run pnpm install --frozen-lockfile and pnpm check, then python scripts/verify-advanced-fixtures.py, python scripts/verify-audio-fixtures.py, and python scripts/verify-polyglot-fixtures.py. Large-download acceptance additionally uses developer Poppler/pdfinfo and writes a temporary browser download of about 512 MiB; neither that file nor the test harness is published. Normal regression tests block service workers for deterministic interception; dedicated offline flows explicitly allow the real production worker. Test worker discovery excludes Angular's worker-basic.min.js fallback script.

The existing approximately 5.2 kB generator-style warning and CSS Tree optional source-map CommonJS warning remain non-fatal build warnings. Actual Safari/iOS, Android, broader device/consumer acceptance, deployment automation and publication remain Milestone 10 or separate authorized release actions. The reviewed Windows WebKit OPFS/codec limitation is unchanged.
